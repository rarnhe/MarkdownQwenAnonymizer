# MarkdownQwenAnonymizer

调用本地 `llama-server` / Qwen GGUF，对 Markdown 法律文档进行可逆脱敏。该仓库是**独立项目**，仅参考 `AnydocVisionExportMarkdown` 的模块分层与双轨 CI 报告方式；不包含 AnyDoc、JXA 或 WASM 源码。

## 架构

```text
src/
├── core/
│   ├── types.ts       # 抽取数据结构与接口
│   ├── grammar.ts     # GBNF 强控 JSON
│   ├── store.ts       # 跨 Chunk 全局去重 + 正则兜底
│   ├── chunks.ts      # 20,000 字符切片 + 50 字符重叠
│   ├── dates.ts       # 日期识别与原文保护
│   ├── numbers.ts     # 身份证/手机号/统一社会信用代码识别、金额保护
│   ├── mapping.ts     # 中文姓名/机构缩写、冲突编号、NUM 映射
│   └── processor.ts   # 递归处理与同级新目录输出
├── ports/file-port.ts
├── adapters/
│   ├── node-fs.ts     # Node 文件系统
│   └── llama-server.ts# CoT 探测、GBNF、HTTP 400 重试
└── hosts/node.ts      # CLI 入口
tests/
├── fixtures/          # 虚构的 Markdown 测试材料
├── huggleface_downloader.py
├── unit.test.ts
├── run-live.ts
└── summarize-ci.cjs
```

## 下载模型与启动服务

安装 Node.js 24+，在仓库根部运行：

```bash
npm ci
python -m pip install 'huggingface_hub>=1,<2'
python tests/huggleface_downloader.py
```

模型保存为 `tests/qwen2.5-0.5b-instruct-q4_0.gguf`。

macOS 安装并运行 `llama-server`（CPU 示例）：

```bash
brew install llama.cpp
llama-server -m tests/qwen2.5-0.5b-instruct-q4_0.gguf -ngl 0 -c 8192 -b 512 -ub 128 -t 4 --host 127.0.0.1 --port 9931
```

Windows 已安装 `llama-server` 时：

```powershell
llama-server -m ".\tests\qwen2.5-0.5b-instruct-q4_0.gguf" -ngl 0 -c 8192 -b 512 -ub 128 -t 4 --host 127.0.0.1 --port 9931
```

这是纯文本 GGUF，**不要将相同 GGUF 传给 `--mmproj`**；该参数是多模态投影文件参数。GPU 支持时可根据显存调整 `-ngl`。

另开终端脱敏一个文件夹：

```bash
npm run anonymize -- /absolute/path/to/cases
```

工具递归处理 `.md`、`.markdown`，在输入目录同级产生 `cases_脱敏后`，再次运行产生 `cases_脱敏后 2` 等以避免覆盖。所有文件共用一套实体映射；身份证、手机号、统一社会信用代码按各自结构脱敏，其他合同号/案号等使用 `NUM` 占位符。保留源目录层级，默认不跟随符号链接。

### 隐私与错误处理

输出目录根部 `.anonymize_map.json` **以明文保存全部实体原值**，仅用于受控恢复；切勿公开或提交至 Git。生成时尝试采用权限 `0600`。调用服务器失败、JSON 格式错误时直接停止，不静默生成未经完整审查的文档。小模型可能漏识别，发布之前仍需人工复查。

## 双轨测试

```bash
npm run typecheck
npm run test:unit
npm run test:live   # 需要本地 9931 端口的 llama-server
```

`.github/workflows/test.yml` 在 `macos-latest` 上执行静态检查、单元测试、官方 GGUF 下载、真实 llama-server 与端到端测试。每次运行生成 `test_report.md` 并上传日志，无论成功失败都会记录状态；功能分支 push 会自动写回报告，忽略仅报告变更防止 CI 循环；任意必要步骤失败则整个 job 失败。

### 模型权重为何不直接纳入 Git

官方 Qwen Q4_0 GGUF 约 429 MB，超过 GitHub 普通 Git 文件的 100 MB 限制。此仓库提交官方下载器并将模型自动下载到 `tests/`，**并未把真实 429 MB 二进制提交到 Git**。如果必须版本控制该文件，则需要配置 Git LFS、上传真实 LFS 对象并确保有足够额度；单独提交 LFS 指针不能代替实际权重。

测试 Markdown 使用虚构身份及号码，供功能验证，不能代表隐私合规认证。


## 中文友好脱敏规则（PR #1 更新）

- **日期数字保留原文**：支持 `2025年`、`1970年1月1日`、`2026.09.08`，也识别有效的 `YYYY/MM/DD`、`YYYY-MM-DD`。即使模型把 `2025` 误当编号抽出，原文日期片段也不会被数字映射覆盖；真正的身份证、手机号、合同号等仍使用 `[NUM_001]` 编号。
- **姓名**：`许惠茹` → `[许*茹]`；`何然` → `[何*]`；`何瑞` → `[何*-1]`。三字或更长保留首末字；两字保留首字；候选标签重复则后续依次 `-1`、`-2`。
- **机构名称**：`深圳腾讯计算机有限公司` → `[腾*司]`；`腾讯公司` → `[腾*司-1]`。先剔除**开头**受支持的省市行政区划（如 `广东省深圳市`、`深圳市`、`深圳`），随后按首末字生成简写；不删除名称中间的地名。区划表是启发式，未覆盖所有区县，请人工核对。
- **全局唯一、可逆**：整次目录处理只建立一份映射；同一真实值始终获得相同标签，不同真实值不能共享标签。若源文档已含形如 `[何*]` 的字面值，会自动避开该占位符以减少反脱敏歧义。`.anonymize_map.json` 仍保存占位符→原文的可逆字典，须严格保密。

以上变化位于 Markdown 后处理层；用于本地 Qwen 抽取四个 JSON 数组的 GBNF 约束保持不变。此方案追求可读性，首末字仍会泄漏部分姓名及机构信息，因此它是**部分遮蔽**，不等价于对抗重识别的匿名化。


## 中国常见数字脱敏规则（PR #1 后续更新）

- **居民身份证（18 位）**：保留前 6 位行政区划码，其余 12 位遮蔽，例如 `429114199001010018 → 429114************`。同一前 6 位出现多个不同身份证时，改为保留末位校验字符，例如 `429114***********8`、`429114***********6`；若末位也相同，为保证可逆映射唯一，再附加编号后缀。
- **中国大陆手机号码（11 位）**：保留前 7 位，后 4 位遮蔽，例如 `13485791234 → 1348579****`。若多个号码遮蔽后相同，则附加 `-1`、`-2` 等编号，避免反脱敏映射冲突。
- **统一社会信用代码（18 位）**：保留前 8 位，后 10 位遮蔽，例如 `91440300MA5F6WXY12 → 91440300**********`。同一前 8 位出现多个不同代码时，额外保留末位校验字符，例如 `91440300*********2`。
- **美国 SSN**：忽略，不加入映射，不替换原文。
- **金额**：忽略，例如 `60000万元`、`3000元`、`人民币5000元`、`￥3,000`。金额及其数值片段会在映射阶段受到保护，防止模型只抽取金额中的数字后误替换。
- **其他合同号、文件号、案号等**：继续使用可逆的 `[NUM_001]` 编号。
- 日期保护仍然有效；数字分类和掩码均在后处理层完成，GBNF 四字段 JSON 契约不变。

数字脱敏同样使用全局唯一映射。身份证/统一社会信用代码碰撞时显示校验字符；如果校验字符仍不足以区分，或手机号掩码相同，则使用编号后缀，避免两个不同原值覆盖同一反脱敏键。
